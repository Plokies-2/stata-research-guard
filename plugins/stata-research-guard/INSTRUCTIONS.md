# Stata Research Guard: maintained contract

This file records the plugin's binding workflow contract. The skill remains the operational entrypoint; this document makes the current reporting, provenance, and validation boundaries easy to audit.

## Preserve existing projects

Use the smallest compatible change. Preserve established entrypoints, call order, filenames, estimate handoffs, workbook and sheet names, and input/output interfaces. Do not split, rename, or replace an existing workflow to fit a template. Prefer direct stage do-files for preprocessing. A `program` is allowed only when a direct module cannot provide a required interface and the necessity, narrow scope, and input/output contract are recorded.

At every atomic implementation step, write only the statements required by the current input and output state. “Minimal” means no hypothetical extensibility, not compressed or cryptic code. Do not add options, branches, macros, loops, programs, registries, dispatchers, or caller arguments for outcomes, sheets, specifications, or reuse that the current request does not contain. Never encode research choices in positional job strings for downstream `word` parsing. A one-item list stays a direct block. A helper used once stays a direct block. Repetition may justify abstraction only when that repetition is present now and the required interface cannot be expressed directly. Prefer visible sequential blocks or one flat loop over a plain declared list; structural depth 4 or greater is a review warning requiring simplification, while loop depth 3 is the blocking threshold.

Reserve `global` for an intentional cross-do-file interface. Setup may define shared directory roots, but a leaf input or output filename used by only one child do-file belongs in a `local` beside that consumer's first use, or directly in the command when used once. Keep a leaf filename global only when two or more do-files intentionally share that exact artifact contract. Repeated regression-specific controls, sample conditions, event-study RHS terms, fixed effects, and clustering definitions belong in `local` macros beside the consuming specifications; keep a one-use list explicit in the command when that is clearer. Same-file event selectors, coefficient order, axis labels, reference position, and graph notes are also local; use a literal when it is clearer and used once. Existing macro names are preserved as integration interfaces only when they are genuinely public across do-files, not merely because fingerprinting found them. Format long variable, outcome, estimate, coefficient, and option lists as meaningfully grouped multiline blocks with whitespace alignment; keep short lists on one line and never reflow quoted labels, paths, notes, or other text where whitespace is data. Use `///` only when the immediately following physical line continues the same command, indent continuation lines beyond the command's starting indentation, and omit it from the final option or physical line; a blank line, comment-only line, closing brace, `end`, or new command must not follow it.

For a Top 100 command explanation or example-coverage audit, call `inspect_top100_command_examples`; it returns every materially distinct guide block required by that command's complexity and keeps paper-code context separate from exact reusable support. For every substantive atomic authoring transition, call `resolve_transition_evidence` first. Its guide-mechanics and research-usage layers are independent and do not compete on a score: always retain the bounded guide card when found, but never let it supply a sample, estimand, model, fixed effects, VCE, key, axis, sheet, or output placement. When an exact contract/version/facet leaves one guide mechanic, return it as the non-writable companion; when material guide ambiguity remains, return no code and `selection_required`. Paper-occurrence support is a separate, reference-only layer and never generation authority. Harmless setup, declared input loading, inspection, assertion, naming, logging, and other direct primitives need no template. A `variant_group` contains alternatives, so never splice competing variants. Before copying a usage template, compare its six-field `template_input_profile` with the observed topology. A known mismatch rejects that candidate as a template, not the requested work; retain the rank-relative nearest usage candidate only as a nonbinding hint when no template genuinely fits.

Read and apply `skills/stata-replication-workflow/references/general-rules.md` before writing or adapting code. The general rules govern template selection, binding, adaptation, verification, and direct implementation. Select a usage template only when permitted bindings leave the complete atomic transition intact and return it with the guide card. If its frame, algorithm, control flow, interface, or output contract must change, stop calling it a template; split at a natural state boundary when possible, otherwise use `general_rule`. Never turn a guide card into generation authority. Retain the highest-ranked inspected usage candidate only as a nonbinding hint and state that nearest-by-ranking may still be absolutely distant or incompatible. Record `nearest_template_hint=<label_id|none>`, `template_status=<no_suitable_template|wrong_selection|project_specific_contract>`, and `hint_used=<borrowed idea|none>`. General rules implement only an already-declared atomic transition and never fill an unresolved sample, estimand, merge key, model, event axis, sheet group, or output placement. Use `report_policy: required|optional|disabled`; an explicit no-report request selects `disabled` and must not create or modify `report.md`. The legacy `require_report` option is a compatibility alias for `required` when no explicit report policy is given. Under a required policy, create or update root `report.md` with one row for every selected template and every substantive `general_rule` span using the exact `.do` path and one-based inclusive line range. Harmless primitives are not rows. Legacy `general_rule_fallback` rows and `fallback_trigger` fields are accepted only for read compatibility. Keep provenance markers out of the research code and call `audit_stata_project` with the selected report policy.

Canonical summary-statistics construction is substantive rather than a harmless summary primitive. Search `descriptives.summary_dataset`, `exports.descriptive_excel_sheet`, and `figures.descriptive_bar`; compose only source-backed AER/AEJ atoms whose state contracts connect. A one-off `summarize` or `tabstat` used only for inspection remains harmless, but a saved summary dataset, paper workbook, or figure does not.

Path layout and master calls follow the prompt or existing interface. When creating a master do-file, write one Korean comment sentence immediately above every individual `do` call explaining that called file's project-local role; a filename-only comment is not enough. Lint the new master with `lint_do_file(role: "master")`. Manual-root and direct-master-call spans are reference evidence, not forced first-build templates.

## Audit scope and intent contract

`audit_stata_project` uses the active reachable workflow by default: start at `scope.entrypoints` or the selected top-level master, follow reachable Stata calls, and inspect the producer-consumer edges needed by that workflow. Callers may explicitly select `scope.mode: all` or provide project-relative `scope.include_paths`/`scope.exclude_paths`. Excluded directories are pruned before discovery limits and call-graph construction. Unreachable files are listed separately without full lint and do not block the active workflow unless the caller explicitly brings them into scope. Multiple plausible top-level masters produce `needs_review` with no arbitrarily selected active workflow until `scope.entrypoints` is explicit. Scope is a general contract, not a project-specific exception.

Review-only intent is bilingual and wins over incidental write vocabulary. Signals such as 검사, 점검, 평가, 진단, 검토, 발전 가능성, 수정하지 않는다, `review`, `audit`, `inspect`, `assess`, `diagnose`, `explain`, and `do not modify` set `code_required: false` and `write_authorization.status: not_requested`. The planner must not turn such a request into `add_feature`, load writable templates, or schedule a project write. This no-write boundary also overrides caller overhaul modes. An explicit write request is actionable only when it is not contradicted by the no-change boundary.

Role findings are conditioned on `authoring_state`: a missing role sentence is an error for a new master, a warning for a modified master, and not a retroactive block when an existing master is only audited. This role/state distinction applies generally to master files and is separate from the active-scope decision.

With `report_policy: required` (or the compatibility alias `require_report: true`), report coverage is checked against caller-authored `authored_spans` for substantive transitions with confidently known boundaries. One contiguous row with a valid one-based bound is required for each such span; harmless primitives, provenance markers in research code, and untouched legacy files are not silently made mandatory. `optional` allows omission, while `disabled`—including an explicit no-report request—prohibits creating or modifying the target `report.md`. An uncertain boundary is `pending`/advisory rather than fabricated coverage.

Multi-sheet and estimate-multiplicity findings use execution-ordered project-level producer-consumer evidence and call-time macro values, not isolated do-file guesses. Producer, durable-estimate, macro, workbook, and sheet state is isolated across disconnected workflow components. A later producer or a durable `.ster` file does not satisfy an earlier in-memory estimate consumer. Dynamic or runtime-only names remain `context_pending` and nonblocking until evidence is available. Runtime success, static audit, and substantive validity are separate statuses: no main log leaves runtime `not_checked`; static source checks cover only certain structural risks; runtime `e(b)` readback requires a nonempty declared nonreference contract; and substantive estimand interpretation remains a separate judgment.

Native Stata `python script <declared .py>, args(...)` is explicit script integration and is not a shell, `winexec`, Unix, bang, or inline Python process escape. It is not a `process_escape` blocker solely for being native integration, but runtime success and output effects require separate runtime/output checks. The existing process-escape blocker remains for shell/winexec/bang/inline escapes.

Derived canonical or template evidence is conservatively marked `independent_support=false` and excluded from independent external-evidence counts. It may document lineage, but repeated self-derived material cannot count as independent support. Deposited external packages remain a separate evidence class. The tool does not perform target-relative package-lineage comparison, so their `independent_support` flag is not proof of different target lineage.

`loop_depth` is active executable loop nesting. `structural_depth` is nested executable/control-block depth, including conditionals, loops, and program blocks. `loop_depth >= 3` blocks; `structural_depth >= 4` is a review warning. Report and enforce these measures separately.

Use `merge.m1_complete_match_assert.v1` for an unconditional `m:1` complete-match contract, preserving merge, assertion, and indicator cleanup as one transition. Use `dataset.finalize_declared_inventory_order_sort_save.v1` for an approved final dataset's declared `keep`, `order`, `sort`, `compress`, and `save` interface; attach persistent-variable labels where each variable is created.

Write reader-facing do-file comments only for project-local state transitions: input meaning, a new variable's formula or definition, a retained merge or filter rule, the active sample or specification, and the purpose of an output. Do not put journal or repository names, template or source names, internal label/checkpoint/substep IDs, source paths, or provenance markers in generated comments. Keep those details in session or audit evidence. Preserve a source name in a comment only when that source is itself part of the project's data-acquisition contract.

## Final regression Excel contract

The direct no-program one-sheet path must name an explicit `.xls` target. The canonical `outreg2_xlsx` formatter writes `.xlsx` and is available only when one workbook requires two or more sheets, including 2SLS first-stage placements.

Final regression Excel uses direct visible `outreg2 replace/append` statements when a workbook has one sheet, regardless of outcome or model-column count. Compute every dependent-variable mean with `quietly summarize <depvar> if e(sample), meanonly`, bind `r(mean)` to a local, and use only `adjr2 addstat(Dep. variable mean, <that local>)`; no other row-changing option is allowed. Use the canonical `outreg2_xlsx` formatter only when one workbook requires two or more sheets; there it assembles the two statistic rows from named estimate states at declared precision. Both paths preserve every raw `outreg2` header, coefficient, standard-error, omitted/base, and note row.

When a specification uses treatment-by-year or another Stata factor-variable interaction, put the factor-variable expression directly in the estimation command. For a conventional event-study RHS with a declared window, write one flat native factor term for every nonreference level, such as `2015bn.time#1.treatment 2016bn.time#1.treatment`; the declared design reference is absent. Do not use plain `i(<numlist>)`, `ibn(<numlist>)`, or a second base marker. Use a single `#`, not `##`, because `##` adds factor main effects to raw `outreg2` output. A separately justified heterogeneous slope such as `year##c.baseline_control` inside `absorb()` remains valid. Do not manually generate `treat_y2015`, `_y2015`, or similar event dummies and do not rename native coefficients. Runtime verification must confirm that every declared nonreference level appears in `e(b)` under the exact raw token Stata returns, including any retained `bn` marker on the first no-base term or estimator-created `o` marker, and that the declared reference contributes the only designed display gap. The Excel source table must expose raw coefficient names, and event-study selectors must target those same names directly. Event-study graph text is English only. Other graphs that display Korean text must use `Malgun Gothic`.

Treat the coefficient/standard-error table emitted by `outreg2` as the raw source of record. Preserve its native coefficient rows and note rows; do not add `keep()` merely to make the workbook shorter, and do not filter, synthesize, rename, or reconstruct coefficient rows during packaging. The final assembly may order the visible table, place it into sheets, add the separately stored adjusted R-squared and dependent-variable mean, and set readable formatting. When an existing Dropbox result is the declared baseline, compare every contracted outcome, sample, and specification for coefficient, standard error, and base/omitted status; a representative-cell match is only a smoke test.

For 2SLS, preserve or restore each first-stage estimate through the estimator's native returned-state interface and pass it through this same raw formatter as an explicitly named model-role group. Add only adjusted R-squared when defined and the first-stage dependent-variable mean. Do not add first-stage F statistics, custom coefficient filters, or renamed rows to the Excel assembly.

Treat estimate replace/seed, append, numbered `.ster` load, in-memory store, and restore as separate state transitions. A named sample-flow `postfile` is permitted only when the researcher supplies the checkpoint meanings and order; declare typed rows, post named counts, and `postclose` it without disturbing the active data. Never use it to reconstruct coefficients or tables.

Before retrieving code, decide whether the request needs a code change. Review, audit, diagnosis, and explanation remain read-only. For a code request, classify the bounded footprint, apply the general rules, inspect genuinely relevant templates, and use a close block only when it completely fits after permitted bindings. If the selection is wrong, headword mapping is incomplete, or no suitable block fits, retain the rank-relative nearest candidate only as a hint and implement the smallest declared transition as `general_rule`. Partial repair is the default, and a caller-supplied overhaul flag cannot widen a narrow request without explicit user intent or concrete incompatibility evidence.

Before an overhaul write, show one display-ready tree containing the exact files and folders to create, modify, move, rename, or delete. Show every planned persistent analysis variable with its reader-facing description, source or exact formula, unit and observation level, creation file, period/geography, coding/missing rule, and use, or state explicitly that none will be created. State whether the project-root `README.md` will be created or amended, and retain the approved actual tree and variable dictionary there as researcher documentation. Wait for explicit approval, and show the revised tree and variable table again if the plan changes. Preserve a compatible existing structure. Do not add a dependency inventory, installation code, packaging manifest, or deployment scaffold unless the user separately requests it.

Programs are not categorically prohibited. The one standing exception is the canonical `outreg2_xlsx` formatter, and it is allowed only when one workbook requires two or more sheets. A one-sheet workbook must not define or call it. The formatter consumes an ordered list of readable in-memory estimate names and may package their raw output into the specified workbook and sheet. It cannot assume a fixed number of specifications, run regressions, reshape or clean research data, choose groups or labels, rewrite raw headers, rebuild coefficients, or hide iteration. The active loop depth is at most two everywhere; depth two requires the explicit substantial-repetition contract. Separately, `structural_depth >= 4` is a review warning; it is not a loop-depth error.

Before selecting the final-Excel implementation, record the full output flow: each outcome's variable label or prompt meaning, definition and measurement relationship, unit and transform, estimation sample and estimand, estimate handoff and specification order. Define each reader-facing `sheet_group` once from substantive evidence about what a reader should compare together; no single metadata field must match, and similar names alone never establish a group. Record workbook, sheet, and sample as a separate placement plan. For one sheet per workbook, keep regressions and `outreg2 replace/append` calls visible and avoid a one-use program, a one-path global, unnecessary estimate store/restore, scratch import/export, and Mata-only cosmetics. When a workbook has two or more sheets, store or restore the required estimate states under readable names and pass each sheet's ordered names to `outreg2_xlsx`, including a separately grouped first stage. Every declared formatter option must be used.

Plan event-study `axis_group` independently from `sheet_group`; it is usually finer. Automatic y-axis scaling is the default. Use a common fixed range only for genuinely close, directly comparable outcomes under the same specification and sample comparison and with the same coefficient unit and transformation. Record explicit membership evidence and the basis for the numeric minimum, maximum, and step. Do not infer a fixed range from sheet membership and do not force fixed axes for every event study.

For exactly one event-study outcome, use the direct no-loop automatic-axis template. For two or more outcomes, use one flat outcome loop with the comparison/sample legend below the axis, raw outcome variable name alone at the top, and immediate PDF export before the loop closes. A fixed axis option is allowed only for a separately declared genuinely close-outcome group; every other outcome keeps automatic scaling. Do not create a graph-job registry, positional dispatcher, or nested loop.

Keep installation commands and installed-command probes out of analysis do-files. Run the requested analysis directly and let an unavailable command fail plainly instead of adding setup files, version tables, or preflight branches to the research project. Direct safe primitives do not authorize dependency probing.

Iteration is allowed, and only the final frozen source is judged. Revise from concrete lint, runtime, or output evidence. If a template requires changes to its frame, algorithm, control flow, interface, or output contract, discard it instead of patching it into a hybrid. Select another complete block, split at a natural state boundary, or use `general_rule`. Under `report_policy: required`, record substantive general-rule ranges in root `report.md` with `nearest_template_hint`, `template_status`, and `hint_used`, not in research-code markers; under `optional` or `disabled`, follow that policy instead. Prefer one flat loop; allow depth two only when two plain lists or numeric ranges repeat the same mechanical body and substantially reduce duplication without hiding research or output choices. Never use depth three. Keep shallow indentation, visible specifications, and no positional jobs, registries, dispatchers, one-use programs, unused options, future-facing interfaces, unnecessary variables, manual event dummies, coefficient reconstruction, or project-specific framework rules. Lint immediately and remove all superseded variants before freezing.

## General-purpose example gate

Indexing a stage is not enough. Every reusable label must receive the raw-source, hash, context, and external-evidence rubric review plus a compact source-evidenced `input_signature`: data shape, record unit, time structure, keys, and relevant variable traits. Record panel length or year/wave span, balance, frequency, units, and transformations only when observable; use `unknown` rather than guessing from names. Compare the target signature before ranking, block known mismatches, and inspect unknowns. Scope and quality are separate: prefer a compatible `general`, then a matching `method_specific`; auto-select only `preferred_candidate` or `conditional_candidate` with an explicit promotion record. Keep `reference_only` visible for diagnosis but do not copy it automatically; legacy implicit autos and all generated guide/usage cards are reference-only. Concrete variable/key/file/data-shape bindings are normal when isolated in `minimal_edit_fields`; penalize only harmful coupling in control flow or hidden state. Hide `project_specific` blocks from default generation. The multi-sheet Excel formatter is the only current user-approved canonical exception. `negative`/`exclude` labels are explanation-only. A method or state explicitly named by the request is a compatibility condition before scope/readability ranking.

Within a compatible state, prefer the shortest block with explicit inputs and outputs, no author-only helper, no machine path, and no hidden data convention. Raw corpus text is evidence only. When no suitable template exists, `general_rule` may implement the declared contract from locally verified mechanics while retaining the rank-relative nearest candidate only as a hint; this does not create a new label.

## Provenance and validation

For code creation or revision, the planner defaults to `report_policy: required`; a standalone read-only audit defaults to `optional`. Under `required`, root `report.md` uses the exact header `| mode | target | lines | checkpoint | label_id | reason |` and the modes `template` and `general_rule`; if neither was used, state `No template or substantive general-rule spans.` Under `optional`, omission is permitted. Under `disabled`, including an explicit no-report request, do not create or modify the file. This lightweight debugging record does not replace the opt-in schema-2 template-reuse manifest. Under a required policy, the completeness check is limited to caller-authored substantive `authored_spans`; it does not require rows for harmless primitives, provenance markers in research code, or untouched legacy files. Legacy report vocabulary is read-only compatibility and must not be emitted.

For every chosen labeled checkpoint, retain enough session evidence to identify the selected block and edits. Do not create a project manifest by default. `template_reuse_check` is for explicit persistent audits or existing contracts; by default it reports a skipped compatible template as an advisory. Strict template-reuse blocking is opt-in. `general_rule` substeps may reflect a prompt-defined formula, a dictionary gap, or a template mismatch with the rank-relative nearest candidate retained only as a hint.

If the user identifies an existing `.do` file as the frame for a lightly adapted sibling, use `plan_dictionary_repairs.source_reuse` instead of adding estimator-specific detection or regenerating the file. Declare the canonical source, destination, and every allowed literal edit with its exact expected occurrence count. Prune unrelated trees with planner scope, copy first, apply only declared edits, and require an exact `candidate_path` match; any undeclared difference blocks the adaptation.

An installed plugin verifies corpus source bytes through its SHA-addressed `data/source_archive` when the development corpus is unavailable. Prefer an approved live original when present; otherwise require the archive index path, byte count, and SHA-256 to agree. Rebuild the archive after any runtime-label or cited-source change.

Treat existing blind-generation artifacts and runtime outputs as baselines only. They do not establish a final runtime verdict. Before declaring final readiness, run the current source in a source-isolated clean trial from clean generated, `ster`, `table`, and `figures` state or an equivalent clean room; retain the fresh `do/main.log`, exact artifact counts, and directly calculated file hashes in the audit result. The Top 51–100 guides are source/static audited only, not runtime validated. Static checks, workflow-reproduction checks, and baseline comparisons remain supporting evidence rather than substitutes for that trial.
