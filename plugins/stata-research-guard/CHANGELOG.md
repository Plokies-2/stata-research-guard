# Changelog

## Unreleased

- Remove every internally authored executable example except the explicitly approved canonical `outreg2_xlsx` multi-sheet formatter: 35 derived implementations, one project path snapshot, two legacy manual-derived labels, the package-first compact registry, and their source snapshots and archive bytes. Derived formatter reuse now requires an exact label, source path, source-file hash, and code hash match.
- Convert all 454 official/maintainer guide atoms into code-free `reference_only` command metadata with authoritative URLs, state/input contracts, and `code_available=false`. Guide bodies no longer enter labeled ranking, resolver output, Top-100 command reports, or MCP projections; only deposited researcher code may serve as a general writable usage candidate.
- Rebuild the existing 100-group command-to-evidence map as metadata-first output, retain the 109 deposited code blocks separately, and classify the nine manual-derived Stata runtime fixtures as adapted, non-verbatim, non-selectable, non-independent verification inputs rather than official source code or templates.
- Add fail-closed provenance, stale-artifact, ranking-invariance, and metadata-projection regression contracts so a future internal or guide code body cannot re-enter selection, scoring, source archives, or user-visible command evidence.

## 0.3.0 - 2026-08-28

- Promote the researcher-readability overhaul to the `0.3.x` release line and document the plugin-specific house style in both canonical and public READMEs. The house style covers the cleaned-panel workflow boundary, exact master Input/Output contracts, consuming-file globals, zero-depth regression specifications, lexical locals, shallow loops, restrained modularity, runtime-gated compact event syntax, named sample flow, and exact `e(sample)` means.

- Reduce default context without changing the 14-tool MCP surface or Stata lint/audit behavior: make `SKILL.md` a progressive-disclosure router around the maintained general rules, shorten root/MCP/UI entry instructions, replace twelve duplicated default prompts with five task-mode prompts, and share repeated checkpoint enums through local JSON Schema `$defs`. Add explicit initialize/tools-list context budgets and schema-reference regression checks instead of requiring the same policy wording on every prompt surface. Forward comparisons retain the existing named sample-flow counts and exact `quietly summarize ... if e(sample), meanonly` one-sheet mean contract after the first compact draft made them too easy to miss, and keep runtime-unverified compact event syntax out of the main prompt so it does not become the automatic generation choice.
- Defer five large, independently used evidence indexes until their owning MCP tool is first called, while caching each successful load and preserving fail-closed corruption handling and the Top 100 missing-file advisory. Reuse one LCS result in template-retention checks, require exactly one `lint_do_file` source, reject invalid report/scope enums at runtime, and make unavailable-Stata tests return immediately after `t.skip()`.
- Replace the exceptional `general_rule_fallback` authoring model with always-on general rules. Templates are now optional complete specializations: selection, binding, adaptation, and verification all follow the general rules, and any change to a template's frame, algorithm, control flow, interface, or output contract ends template mode. New resolver routes, reports, and schema-2 manifests use `guide+general_rule`, `general_rule`, `template_status`, and `general_rule_justification`; legacy fallback/native vocabulary remains read-only compatibility.
- Expand the audited command contract to Top 100: 100 ranked groups/395 material variants, retaining the frozen Top 50 prefix (50/203) and 15 supplemental groups/48 variants for 443 contracts. Complexity-weighted sufficiency forbids fixed per-command quotas: a simple bounded state may need one guide atom, while each material input, grammar, inference, support, persistence, or output dimension requires its own atom.
- Add `inspect_top100_command_examples` and the 100-row `top100_command_evidence_matrix` JSON/Markdown outputs. The original release retained guide bodies; the Unreleased provenance cleanup above migrates all 454 guide records to code-free metadata while preserving 109 deposited paper-code blocks in a separate ledger.
- Add `resolve_transition_evidence`, which always returns one bounded guide-mechanics card when available and independently matches at most one research-usage example. Guide and usage scores never compete; profile contradictions, unresolved choices, and unrelated multi-command requests fail closed into fallback, selection, or split routes.
- Complete the independent promotion audit for 454 guide atoms (262 historical + 192 Top 51–100): all are retained as `reference_only`, all have `auto_selectable=false`, and runtime/selector checks remain `not_run`. Fourteen bounded mechanics were added, four overly generic/duplicate variants were narrowed or replaced, and 15 multiline source spans were repaired before the final 192/192 pass-reference-only re-audit.
- Generate 454 guide cards and 166 research-usage examples, all `auto_selectable=false`. The usage layer combines 128 historical rows with 38 schema-2 paper-occurrence support rows; legacy 46 implicit autos are now reference-only. Preserve 19 bounded AEA/openICPSR support rows as explanation-only evidence; the new corpus audit records 132 occurrences (38 pass-reference-only, 13 follow-up, 81 rejected) and 21 exact-contract proposals without copying raw paper code.
- Expand the registry-driven package-first command catalog to 43 official and community Stata families and 109 canonical anchors. `build_reference_data.py` indexes `estpost` and `eststo`, distinguishes `ivreg2` from `ivreghdfe`, preserves canonical names such as `export_excel`, and emits corpus-coverage data in `data/package_command_catalog.json`. The documented expansion path is a command-index plus state-compatible atomic template, not an unbounded estimator-detector list; TeX, install/probe code, and manual coefficient reconstruction remain excluded or quarantined.

- Add an estimator-agnostic existing-file clone template to `plan_dictionary_repairs`: callers declare one canonical `.do` source and exact permitted literal edits, candidates block on every undeclared difference, and planner include/exclude scope prunes unrelated trees before inventory limits.
- Treat an indented continuation line after a comma as an option continuation and recognize `merge ..., assert(...)` as an inline retained-state contract.
- Define `audit_stata_project` active-reachable scope as the default, with explicit `scope.mode: all` and `scope.include_paths`/`scope.exclude_paths` alternatives; prune excluded directories before discovery and indexed call-graph construction, list unreachable files separately without full lint by default, and require an explicit entrypoint instead of choosing arbitrarily among multiple top-level masters.
- Make Korean and English review-only/no-change intent take precedence over incidental write vocabulary and expose the `code_required`/`write_authorization` boundary.
- Separate master-call role findings by `authoring_state`: new-master omissions are errors, modified-master omissions are warnings, and existing audited masters are not retroactively blocked.
- Require report coverage only for caller-authored substantive `authored_spans` under `report_policy: required` (including legacy `require_report: true`); do not force provenance markers or complete untouched-legacy coverage.
- Define `report_policy: required|optional|disabled`, with explicit no-report taking `disabled`; retain `require_report` only as a compatibility alias when no explicit policy is supplied.
- Base multi-sheet and estimate-multiplicity findings on execution-ordered project-level producer-consumer evidence with call-time macro values; isolate state across disconnected workflow components, and do not treat later producers or durable `.ster` files as active stored estimates.
- Distinguish native Stata `python script <declared .py>, args(...)` integration from shell/winexec/bang/inline process escapes; validate its runtime and outputs separately.
- Separate `runtime_success`, `static_audit`, and `substantive_validity`; mark runtime `not_checked` when no log is supplied, require at least one declared nonreference term for `e(b)` estimability readback, and keep interpretation as a substantive judgment.
- Mark same-lineage derived/template evidence `independent_support=false` and exclude it from independent external-evidence counts.
- Define `loop_depth` and `structural_depth` separately: loop depth 3 blocks, while structural depth 4 is a review warning.
- Record the validation diet in `review/validation_policy.md`, including checks retained, merged, downgraded, or excluded by default and the cost-versus-error-detection rationale.
